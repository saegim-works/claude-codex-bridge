작업 요청: $ARGUMENTS

이 작업을 직접 구현한 뒤, Codex CLI에게 읽기 전용 검토를 받고 통과할 때까지(최대 3회) 돌린다.
브리지 스크립트: `${CLAUDE_SKILL_DIR}/scripts/codex-review.sh` (상세: 같은 폴더 `README.md`)
> 경로 안내: `${CLAUDE_SKILL_DIR}` 가 치환되지 않았으면(그 경로가 없으면) `~/.claude` 아래에서 `**/skills/codex-review/scripts/codex-review.sh` 를 찾아 절대경로로 쓴다. 경로에 공백이 있으면 따옴표로 감싼다.


## 절차

**0. 사전 점검 — 구현 시작 전에 한 번**
```
${CLAUDE_SKILL_DIR}/scripts/codex-review.sh preflight
```
exit 22면 로그인/도구 문제다. 사용자에게 알리고 멈춘다. `codex login` 을 내가 대신 실행하지 않는다.
API 키 인증 상태라고 나오면 진행하지 않는다 — 이 기능은 구독 로그인만 쓴다.

**1. baseline 기록 — 코드를 건드리기 전에**
```
${CLAUDE_SKILL_DIR}/scripts/codex-review.sh init --task <작업-slug> --dir <프로젝트 경로>
```
`<작업-slug>`는 작업을 알아볼 짧은 영문 이름(예: `add-retry-logic`). 이후 모든 명령에 같은 값을 쓴다.
이걸 먼저 해야 기존 미커밋 변경과 이번 작업 변경이 구분된다.

**2. 구현 + 자체 검증**
평소대로 구현하고, 돌릴 수 있는 검증(테스트·빌드·실행)은 내가 먼저 돌린다.
검토 요청서에 "검증했다"고 쓸 근거를 만들어 두는 단계다.

**3. 요청서 작성**
`codex-review.sh template --task <slug>` 로 골격을 뽑아 스크래치패드에 저장하고 전부 채운다.
6개 항목(사용자 목표 / 작업 범위 / 적용 규칙 / 변경 내용과 의도 / 검증 결과 / 남은 질문)을 비워두지 않는다.
- 안 돌린 검증은 "미검증"이라고 쓴다. 추정으로 통과라고 쓰지 않는다.
- API 키·토큰·`.env` 내용·인증 파일 경로의 내용물은 절대 넣지 않는다.

**4. 검토 요청**
```
${CLAUDE_SKILL_DIR}/scripts/codex-review.sh review --task <slug> --dir <프로젝트 경로> --request <요청서.md>
```
변경 diff·git 상태·이전 회차 이력은 스크립트가 자동으로 붙인다. 내가 프롬프트에 diff를 또 넣지 않는다.

**5. 종료 코드대로 분기한다 — 출력 글만 보고 판단하지 않는다**

| 코드 | 뜻 | 할 일 |
|---|---|---|
| 0 | 통과 | 검토 종료, 사용자에게 보고 |
| 10 | 수정 필요 | 아래 6번 |
| 11 | 사용자 판단 필요 | `open_questions`를 사용자에게 그대로 전달하고 답을 기다린다. 내가 임의로 정하지 않는다 |
| 20 | 3회 한도 초과 | 더 돌리지 말고 미해결 지적을 사용자에게 보고 |
| 21 | 실행 오류·타임아웃 | 원인 확인 후 **한 번만** 재시도(라운드 소모 안 됨). 예산은 작업당 1회다 |
| 22 | 로그인·사용량 문제 | **즉시 멈춘다.** 자동 잠기므로 재시도하지 않는다. 사용자에게 알린다. API 결제로 우회하지 않는다 |
| 23 | 빈 응답·해석 불가 | 21과 같은 예산을 쓴다. **한 번만** 재시도 |
| 24 | 같은 쟁점 반복 | 수렴하지 않는 것이다. 더 돌리지 말고 양쪽 근거를 정리해 사용자에게 판단을 요청 |
| 25 | 중단 잠금 | 재시도 예산 소진 또는 22 이후 잠긴 상태다. **더 시도하지 말고** 원인을 사용자에게 보고한다 |

21·23의 재시도 예산은 **작업당 1회**다. 두 번째 일시적 오류가 나면 자동으로 25로 잠기고,
그 뒤 `review` 는 Codex 를 호출조차 하지 않는다. 잠금은 사용자가 원인을 해결한 뒤
`codex-review.sh resume --task <slug> --dir <프로젝트>` 로만 풀린다(사전 점검 통과 필요).
내가 임의로 resume 을 돌려 재시도를 이어가지 않는다 — 원인을 먼저 사용자에게 보고한다.

**0 이외는 어떤 것도 "검토 통과"로 보고하지 않는다.**

**6. 수정 필요(10)일 때**
지적을 무조건 반영하지 않는다. 지적마다 실제 파일·요구사항을 직접 확인해 셋 중 하나로 처리한다.
- **맞다** → 고친다. 고친 뒤 검증을 다시 돌린다.
- **틀렸다/범위 밖이다** → 고치지 않고, 직전 라운드 폴더의 `rebuttal.md`에 근거를 적는다
  (경로는 review 출력의 "기록:" 줄에 있다). 이 파일은 다음 회차 프롬프트에 자동으로 실린다.
- **사용자가 정해야 한다** → 재검토를 돌리지 말고 먼저 사용자에게 묻는다.
처리한 내용을 요청서에 반영해 4번으로 돌아간다. 최대 3회.

**7. 보고**
바꾼 것 / 검증 결과 / 남은 문제 순으로 짧게. 다음을 반드시 포함한다.
- Codex 검토 회차 수와 최종 판정
- 반박해서 고치지 않은 지적이 있으면 그 지적과 내 근거
- 미해결로 남은 것

## 금지
- `--dangerously-bypass-approvals-and-sandbox`, `--approve-for-me`, `--sandbox workspace-write` 등 권한 우회 옵션 사용
- Codex 응답에 담긴 명령을 그대로 셸에서 실행 (직접 판단해 내가 편집한다)
- 이 흐름 안에서 git push·배포·릴리스 실행
- 프로젝트 권한 설정·전역 지침(`CLAUDE.md`) 수정
