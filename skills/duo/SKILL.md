요청: $ARGUMENTS

Codex 를 **두 번째 머리**로 쓴다. 호출은 전부 공용 브리지 하나로 한다(읽기 전용, ChatGPT 구독):
```
${CLAUDE_SKILL_DIR}/scripts/codex-ask.sh --dir <작업 폴더> --file <질문 파일>
```
모델은 codex 설정값(`CODEX_ASK_MODEL` 로 바꿀 수 있다), 추론 강도는 `medium` 이 브리지 기본값이다.
> 경로 안내: `${CLAUDE_SKILL_DIR}` 가 치환되지 않았으면(그 경로가 없으면) `~/.claude` 아래에서 `**/skills/duo/scripts/codex-ask.sh` 를 찾아 절대경로로 쓴다. 경로에 공백이 있으면 따옴표로 감싼다.

사용자가 올리라고 할 때만 `--effort high|xhigh|max|ultra` 를 붙인다 — max·ultra 는 `--timeout` 도 늘린다.
질문 파일은 스크래치패드에 쓴다. Bash `timeout` 은 600000 으로 준다(스크립트 기본 540초).

## 모드 고르기
요청 앞머리에 `의견`/`아이디어`/`확인` 이 있으면 그대로, 없으면 내용으로 고른다.

| 모드 | 언제 | 흐름 |
|---|---|---|
| 의견 (기본) | 답이 하나로 안 떨어지는 어려운 질문·설계 판단 | 각자 답 → 서로 비판 → Claude 종합 |
| 아이디어 | 무엇을 만들지부터 정해야 하는 프로젝트 | Codex 안 → Claude 검토·선택 → Claude 구현 → Codex 검토 |
| 확인 | Claude 가 낸 숫자·결론·판정이 맞는지 | Claude 결론 → Codex 가 근거를 직접 재확인 → 더 나은 방향 |

## 의견
1. **내 답을 먼저 확정한다.** 질문 파일 A 에 질문과 필요한 맥락(관련 파일 경로, 제약, 사용자 규칙)을 쓰고,
   내 답(결론 + 근거 + 자신 없는 부분)은 따로 B 에 적어둔다. Codex 답을 본 뒤 내 답을 고쳐 쓰지 않는다.
2. **Codex 에 두 번 묻는다 — 병렬로.**
   - 블라인드: 파일 A 만 준다. "네 답을 결론·근거·위험 순으로."
   - 비판: A + B 를 주고 "Claude 답에서 틀린 것·빠진 것·더 나은 대안. 동의하는 부분은 한 줄로만."
3. **종합한다.** 비판마다 실제 파일·자료로 직접 확인하고 맞다/틀렸다/모르겠다로 가른다. 무조건 따르지 않는다.
4. 보고: 최종안, **둘이 갈린 지점과 각자 근거**, 내가 받아들인/기각한 Codex 지적. 갈린 지점이
   사용자 취향·결정 문제면 내가 정하지 말고 묻는다.
5. 큰 쟁점이 남았을 때만 종합안을 Codex 에 한 번 더 보여준다(총 3회 호출까지).

## 아이디어
1. Codex 에 목표·제약·기존 코드 위치를 주고 **안 2~3개**(각 장단점, 예상 작업량, 위험)를 받는다.
2. 각 안을 직접 확인한다 — 없는 파일·API 를 전제로 하거나 사용자 규칙(CLAUDE.md·메모리)에 어긋나면 걸러낸다.
3. 고른 안과 이유를 사용자에게 한 줄로 알리고 **바로 구현한다.** 안끼리 취향이 갈려 결정이 필요할 때만 먼저 묻는다.
4. 구현 후 검토는 같은 플러그인의 `codex-review` 스킬 절차를 그대로 따른다.

## 확인
1. 질문 파일에 **내 결론과 그 근거(파일 경로·명령·계산)** 를 적고, "근거를 직접 다시 읽고 재계산하라.
   맞으면 맞다, 틀리면 올바른 값과 이유, 더 나은 접근이 있으면 방향"을 요청한다.
2. Codex 가 다른 값을 내면 둘 중 누가 맞는지 내가 직접 다시 확인해서 가린다. 못 가리면 둘 다 보고한다.

## 금지
- 질문 파일에 API 키·토큰·`.env`·`auth.json` 내용을 넣지 않는다 (스크립트가 가리긴 하지만 믿지 않는다).
- Codex 답에 든 명령을 그대로 셸에서 돌리지 않는다. 판단해서 내가 편집한다.
- Codex 답을 원문 그대로 사용자에게 붙여넣지 않는다. 종합해서 보고한다.
